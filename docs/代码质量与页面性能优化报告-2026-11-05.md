# 代码质量与页面性能优化报告

日期：2026-11-05（Asia/Shanghai）  
项目：`kkk-blog`  
对比基线：`d699fc3c23c2184499d867fffe0a0db013a8255d`

## 1. 交付结果

本次围绕博客首页、文章列表、文章详情、全屏动效和认证边界开展检查并直接修改代码。保留现有页面设计、数据库结构和主要操作流程；没有新增运行依赖，没有执行数据库迁移、修改线上数据或发布部署。

- 将首页独立查询、分页列表与总数查询改为并行执行。
- 文章列表只返回卡片所需数据与摘要，不再将完整 Markdown 正文传给客户端。
- 修复筛选后的分页总数、列表请求竞态、失败重试及重复加载。
- 装饰动效延后加载，隐藏标签页和系统减少动态效果模式下停止运行；补齐资源清理。
- 修正文章更新权限、草稿可见性、受保护编辑路径和认证令牌字段边界。
- 修复检查工具配置，补充 6 组、26 项回归测试，以及可重复运行的离线性能基准。

**已量化的主要改善：测试样本的列表 JSON 从 114,650 字节减少至 3,332 字节，下降约 97.1%。这不是整页体积或真实用户加载时间的改善比例。**

## 2. 检查范围与方法

检查项目说明、依赖、Next.js 配置、Prisma 模型、页面入口、共享组件、文章查询及认证代码，并对源码执行 TypeScript 与 ESLint 检查。重点阅读首页渲染链路、列表分页、详情读取、动效生命周期及会话更新逻辑。

项目实际使用 Next.js 16.2.0、React 19、Prisma 6、Zustand。原 README 仍包含模板说明，不能作为当前所有功能的验收依据。本次没有声称完成全量业务、安全或跨浏览器审计。

验证分为三层：静态检查、使用受控依赖的业务/组件回归测试、执行实际服务函数的离线性能对比。真实数据库、OAuth 登录、页面 Core Web Vitals 与端到端浏览器验证的边界见第 6 节。

## 3. 问题与具体优化

### 3.1 数据查询与传输

| 问题 | 修改 | 预期收益与边界 |
| --- | --- | --- |
| 首页先等待分类查询，再查询最新文章 | `HomeArticleList` 使用 `Promise.all` | 独立任务的等待时间可以重叠；实际收益受数据库连接池与延迟影响 |
| 分页列表和总数串行查询 | `getPostsByPage`、`getMePosts` 并行查询 | 减少独立数据库操作的串行等待 |
| 总数统计所有文章，没有应用分类/搜索/发布状态筛选 | 总数使用与列表相同语义的筛选条件 | 避免错误页数和无效的后续滚动请求 |
| 文章列表返回完整正文，再交给客户端卡片 | 增加 `PostListItem`，返回摘要时剥离 `content` | 减少 Server Action 响应和 RSC 属性传输；详情接口保留正文 |
| 首页分类卡片根本不使用正文 | 关联查询通过 Prisma `omit` 不取正文，限定文章为已发布状态 | 同时减少该查询的数据库返回数据与客户端属性体积 |
| 每篇摘要都重新创建 Markdown 处理器 | 将摘要逻辑移到 `lib/markdown.ts`，复用冻结处理器 | 从共享客户端工具中移走 Markdown 依赖，减少重复初始化；未实测生产 JS 包缩减量 |
| 元数据与详情正文都调用文章读取函数 | 用 React `cache` 包装请求内读取 | 同一服务端渲染中的重复读取和 PV 更新可合并；不引入跨用户共享缓存 |
| 分页参数缺少服务端边界，查询失败可能被包装成成功 | 校验正整数页码及 1–50 条页大小，传递查询失败 | 控制单页工作量，避免把异常伪装为空列表成功 |

最新列表仍需在服务端读取正文才能生成摘要。本次没有新增摘要数据库字段，因此不能宣称所有列表查询都已避免读取正文。列表和总数使用并行独立查询，没有新增快照事务；并发发布/删除时仍可能有短暂的计数差异。

### 3.2 列表交互与渲染

`InfiniteScrollList` 改为以请求代次识别结果：切换分类、搜索或卸载后，旧请求的结果不能覆盖新状态。服务端操作本身不会被强制取消，但旧结果会被丢弃。

加载入口增加同步锁，防止同一轮 IntersectionObserver 回调重复请求。业务失败码和网络异常都进入错误状态，保留失败页码供手动重试；失败后不自动循环请求。空列表、加载和错误状态分开处理，并添加 `aria-busy`、`aria-live` 和错误提示语义。

首页 Banner 与鼠标动效只订阅所需 Zustand 字段，避免无关设置变更触发组件重渲染。返回顶部组件只记录“是否超过阈值”，不再订阅每个滚动坐标；控件改为带无障碍名称的按钮。

### 3.3 装饰动效与资源回收

新增 `BlogEffects` 客户端入口，将 SplashCursor 和 SakuraOverlay 改为 `next/dynamic` 分块加载，在浏览器空闲期启动，并保留原有设置开关。

- 标签页隐藏时卸载动效，重新可见时按设置恢复。
- 遵守 `prefers-reduced-motion`，减少动态效果模式下不启动这两项装饰动效。
- 鼠标流体组件卸载时释放 WebGL 上下文，触摸监听设为 passive；无 WebGL 时跳过初始化。
- 修复 SakuraOverlay 配置对象每次渲染变化造成的重复初始化。
- 修复 Sakura 库没有保存后续计时器/动画帧的问题，停止后不继续生成花瓣，且只清理自身容器内的花瓣。

这些修改减少首屏同步初始化和后台持续工作，**尚未量化 CPU、GPU、FPS、耗电或 LCP 的改善**。前台鼠标流体特效仍然有持续 GPU 开销，默认视觉表现没有被删除。

### 3.4 权限与认证边界

| 发现 | 修复 |
| --- | --- |
| 编辑路径的精确字符串匹配没有覆盖 `/blog/article/write/42` | 按路径边界匹配编辑子路径，并保留登录返回地址的查询参数 |
| 公开请求在判断路由前就执行 `auth()` | 公开路由在 Proxy 内直接返回；根布局自身的会话读取仍然保留 |
| 登录用户更新文章时没有限定作者 | 更新条件同时包含文章 ID 和当前登录用户 ID |
| 个人文章筛选可能覆盖服务端指定的用户 ID | 用 AND 保留所有权和发布状态约束 |
| 详情可能公开他人的草稿 | 非公开文章仅允许作者读取，缺失文章受控返回 |
| 用户 CRUD/按邮箱查询等数据库辅助函数被模块级 `use server` 暴露 | 改为带 `server-only` 标记的内部模块，由已有认证服务暴露所需操作 |
| JWT 回调将完整用户对象复制进令牌，可能包含密码摘要 | 新令牌只写入需要的身份、展示及权限字段 |
| 会话更新将客户端 `session.user` 任意字段合并进令牌 | 仅接受数据库验证后的名称、头像、邮箱；身份和角色保持服务端值 |
| 生产 HTTP 检查发现 Auth.js 缺少 `AUTH_SECRET` 时返回错误对象，被原有真值判断当作已登录会话 | 对应用会话入口统一校验 `session.user.id`；无有效身份则返回 null，配置故障不能放行受保护页面 |

旧版本已经签发的令牌不会因代码文件变动自动失效，本次没有执行强制退出或修改认证密钥。上线前应评估是否需要会话失效/重新登录措施。其他业务服务的权限链路不属于本次完整验证范围。

### 3.5 工程质量

- `lint`、`lint:fix` 改为 ESLint CLI，适配 Next.js 16；增加 `typecheck` 命令。
- 简化 ESLint 配置，删除无效插件配置和未使用的目录扫描函数，排除生成目录。
- Next 配置不再为读取构建开关而提前加载全部应用服务端密钥校验；应用运行时的环境校验仍保留。
- Bundle Analyzer 显式使用 webpack，避免与 Next.js 16 默认 Turbopack 构建方式冲突。
- Jest 添加路径别名与工作区缓存目录，删除“没有测试也通过”的默认行为。
- 旧包分析脚本改用标准模块加载与内置目录创建，删除无用计算，补充失败处理；通过旧格式清单样本验证输出。此项没有宣称已适配 Next.js 16 的新清单格式。
- 移除 GalleryModal 的 `@ts-nocheck`，为滚动动画及 store 辅助函数补充类型，修复导入排序、可使用 const 的声明和空接口。
- 修正个人文章编辑链接中的双斜杠，并将旧 E2E 模板标题断言更新为实际博客标题。

## 4. 性能对比数据

数据见 [原始基准 JSON](performance/benchmark-2026-11-05.json)，脚本为 `scripts/benchmark-performance.mjs`。

测试读取指定基线提交与当前工作区的真实 `getPostsByPage` 实现，并替换数据库、认证等外部边界。样本为 6 篇合成文章，每篇正文 18,000 字节；每个数据库操作注入 30 ms 延迟。各预热 1 次，采样 7 次。没有连接数据库或写入业务数据。

| 指标 | 优化前 | 优化后 | 解读 |
| --- | ---: | ---: | --- |
| 列表响应 JSON | 114,650 B | 3,332 B | 减少约 97.1%，主要来自移除正文 |
| 同一样本 gzip 体积 | 978 B | 490 B | 减少约 49.9%；测试正文高度重复，不能外推到真实文章 |
| 列表中的完整正文字段数 | 6 | 0 | 摘要仍保留，详情正文不受影响 |
| 本机样本服务函数耗时中位数 | 618.68 ms | 420.23 ms | 仅为本轮受控实验数据，不等于页面响应或稳定提速比例 |

本轮计时包含 Markdown 处理与本机调度，且前后顺序采样，没有消除 JIT 和资源竞争影响。时间数据用于辅助观察；主要可靠结论是响应数据量下降，以及测试证明独立数据库调用已经并发启动。

## 6. 环境限制与未验证项

1. 原 `.next/types` 存在 Windows 写权限限制。首次 webpack 构建明确报 `EPERM: operation not permitted, mkdir .../.next/types/app/(auth)`；因此不能把原目录构建记为通过。
2. 增加可选 `NEXT_DIST_DIR`，允许本地独立构建，不覆盖原 `.next`；默认构建目录保持原值。沙箱外的独立构建已成功。HTTP 检查需要让临时服务与请求运行在同一进程会话中，避免沙箱的回环网络隔离；检查后停止临时服务。
3. Jest 默认临时目录也遇到写入/重命名限制，改为工作区内的 `.next-test-cache` 后，测试能够执行。
4. 本机 PATH 优先指向的 Node 管理器无法解析项目版本要求。验证实际使用已有的 Codex Node v24.22.1；没有修改全局 Node/Git 配置或安装新依赖。
5. 未测真实页面 LCP、INP、CLS、生产 JS 包体积和真实数据库执行计划；没有将开发/离线样本耗时标记为用户页面性能。OAuth、真实登录态、真实收藏/文章写入也没有做数据联调。
6. 本地生产配置实际触发 Auth.js `MissingSecret`。已修复该故障下的错误放行，但正常登录仍需要部署环境配置有效、稳定的 `AUTH_SECRET`。本次没有替用户写入持久密钥或修改现有会话。
7. 完成验证的生产构建命令是 `next build --webpack`。默认 `pnpm build` 使用的 Turbopack 构建未完成验证，不计为通过。

## 7. 本地运行与复验

使用项目要求的 pnpm 和有效 Node 环境，保留现有应用环境配置：

```powershell
pnpm dev
pnpm typecheck
pnpm test --runInBand
pnpm lint
node scripts/benchmark-performance.mjs
```

最后一条默认对比本报告的基线提交，也可传入其他基线提交 SHA。脚本会覆盖对应日期的基准 JSON，重新运行的计时可能不同。

独立生产构建与包分析：

```powershell
$env:NEXT_DIST_DIR = '.next-performance'
pnpm exec prisma generate
pnpm exec next build --webpack
# 构建通过后，在相同环境下启动：
pnpm start
# 分析配置使用 webpack，报告输出到所选构建目录下 analyze/：
pnpm analyze
Remove-Item Env:NEXT_DIST_DIR
```

在已安装浏览器的开发环境验证页面：

```powershell
pnpm exec playwright install chromium
pnpm exec playwright test --project chromium
```

浏览器回归重点：桌面/移动端首页、连续切换分类、加载失败后重试、文章详情正文、编辑入口登录跳转、个人资料保存、特效开关、隐藏标签页恢复和系统减少动态效果。然后在生产构建、相同设备/网络/内容样本下采集至少多轮 LCP/INP/CLS，再报告页面级改善。
