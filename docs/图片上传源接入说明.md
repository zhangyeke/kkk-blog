# 图片上传源接入说明

更新日期：2026-11-05。

已将 [695402.xyz/mt 图床页面](https://695402.xyz/mt/)使用的上传接口接入项目，作为通过服务端配置手动切换的备用上传源。默认继续使用现有图床，未改写本地环境文件或线上配置。

**可用性边界：接入代码与回归测试已完成，但本机真实 POST 联调中，第三方主、备节点均返回 HTTP 403，尚未获得一次真实上传成功结果。当前应继续使用默认源。** 403 的具体原因和是否允许第三方项目调用，需要由服务提供方确认。

## 1. 如何切换

在项目实际使用的环境文件中设置，或在部署平台配置以下服务端环境变量。它们不使用 `NEXT_PUBLIC_` 前缀。

| 配置 | 可选值 | 默认值 | 含义 |
| --- | --- | --- | --- |
| `IMAGE_UPLOAD_PROVIDER` | `default`、`mtbed` | `default` | 现有图床 / 本次接入的第三方图床 |
| `MTBED_UPLOAD_SERVER` | `primary`、`secondary` | `primary` | 第三方图床的主 / 备用节点 |
| `IMAGE_UPLOAD_TIMEOUT_MS` | 1000–120000 的整数 | `15000` | 单次上游请求超时，单位毫秒 |

使用现有图床：

```dotenv
IMAGE_UPLOAD_PROVIDER=default
IMAGE_UPLOAD_TIMEOUT_MS=15000
```

选择第三方主节点：

```dotenv
IMAGE_UPLOAD_PROVIDER=mtbed
MTBED_UPLOAD_SERVER=primary
IMAGE_UPLOAD_TIMEOUT_MS=15000
```

选择第三方备用节点：

```dotenv
IMAGE_UPLOAD_PROVIDER=mtbed
MTBED_UPLOAD_SERVER=secondary
```

修改后重启开发/生产服务；部署平台更新环境变量后重新部署。恢复现有图床时，将 `IMAGE_UPLOAD_PROVIDER` 改回 `default` 即可。原有 `IMGBB_API_URL`、`IMGBB_API_TOKEN` 等配置继续保留。

这是手动切换，不会在失败或超时后自动把同一张图片再次发送给另一个服务，以免产生重复文件或出现难以判断的上传结果。已有图片 URL 不会自动搬迁，切换只影响后续上传。

## 2. 接入位置和接口契约

上传链路：

```text
头像 / 文章封面 / 图集 / Markdown 编辑器
  → lib/utils.ts：uploadImagePromise(file)
  → service/fileUpload.ts：uploadImage(formData)
  → 服务端所选上传源
```

前端仍调用 `uploadImagePromise(file): Promise<string>`，成功得到图片 URL，失败会拒绝 Promise 并按调用入口显示提示。编辑器使用自己的上传提示；其他入口由公共上传函数显示错误。

Server Action 的内部结果统一为 `{ code, message, data }`，成功时 `code=200`、`data={ url }`，失败时 `data=null`。仅归一化真实返回的 URL，不补造上游没有返回的宽高、文件 ID 等元数据。

| 上传源 | 地址 | 文件字段 | 请求参数与凭据 |
| --- | --- | --- | --- |
| `default` | 原 `IMGBB_API_URL` + `/api/v3/upload` | `file` | 原 Bearer Token；服务端设置 `dedup=true`、`album_id=1516` |
| `mtbed` / `primary` | [aapi.helioho.st/upload.php](https://aapi.helioho.st/upload.php) | `image` | 不携带现有图床的 Token 和相册参数 |
| `mtbed` / `secondary` | [mtbed.netsons.org/upload.php](https://mtbed.netsons.org/upload.php) | `image` | 不携带现有图床的 Token 和相册参数 |

备用源的成功契约来自该站公开前端代码：`code === 200`，图片地址取 `data.url`。这不代表第三方已向本项目承诺开放 API 或永久存储。

## 3. 校验与错误处理

- 服务端先检查登录身份，未登录不向上游发送图片。此前发现的生产 `AUTH_SECRET` 配置问题仍需按项目认证文档处理，否则上传会返回认证失败。
- 客户端预检和服务端共用大小单位解析；原 `NEXT_PUBLIC_IMG_UPLOAD_LIMIT` 继续生效。支持 `3mb`、`512kb` 等单位，无单位数字沿用 MB 语义。
- 第三方单张上限进一步限制为 20 MiB，实际采用“项目配置限制”和“20 MiB”中更小的值。默认项目大小限制不会自动提高到 20 MiB。
- Server Action 请求体额外预留 512 KiB 给 multipart 字段与边界，避免刚好达到文件上限的合法图片因封装开销被拒绝。
- 检查非空文件与二进制文件头，支持 PNG、JPEG、GIF、WebP、BMP、ICO、可识别的 HEIC。SVG、AVIF 和不能识别的内容会返回格式错误。文件头检查不等同于完整解码校验。
- 上游收到的文件名和 MIME 根据检测到的内容归一化，不信任客户端填写的类型或扩展名。
- 上传目标由服务器配置和固定节点列表决定，不接受浏览器传入目标地址；拒绝上传请求的重定向。
- 只接受含有效 HTTP(S) URL 的成功响应，拒绝脚本协议、空地址和带用户名/密码的地址。
- 对认证、格式、大小、HTTP 拒绝、非 JSON 页面、错误返回、网络错误和响应读取超时分别处理。不会把上游 HTML 或内部堆栈返回给用户。

| 业务码 | 含义 |
| --- | --- |
| `400` | 缺少文件、空文件或参数错误 |
| `401` | 未登录或会话无效 |
| `413` | 超出当前源的大小限制 |
| `415` | 不支持或无法识别的图片格式 |
| `502` | 上游拒绝、异常响应或网络失败；若上游为 403，提示会包含 403 |
| `504` | 上传请求或响应读取超时 |

这些是 Server Action 结果里的业务码，不表示 HTTP 传输状态必然相同。头像与通用图片组件在失败后退出加载状态，保留原图片并允许再次选择同一文件。
