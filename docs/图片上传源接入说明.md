# 图片上传源接入说明

更新日期：2026-11-05。

已将 [695402.xyz/mt 图床页面](https://695402.xyz/mt/)使用的上传接口接入项目，作为通过服务端配置手动切换的备用上传源。默认继续使用现有图床，未改写本地环境文件或线上配置。

**可用性结论（2026-11-07 复测）：此前的 HTTP 403 不是接口下线，而是上游按来源头做防盗链校验——请求不带 `Referer` / `Origin` 时主、备节点一律 403；补齐来源头后两个节点均返回 200 并成功返回图片地址。`service/fileUpload.ts` 已为备用源补上这些请求头（不影响默认源），上传源现已切换到 `mtbed`。** 该第三方源仍属个人图床，存储稳定性不由本项目保证，重要图片建议保留本地副本。

## 1. 如何配置

上传相关只需要两个服务端环境变量（不使用 `NEXT_PUBLIC_` 前缀），写在 `.env.development` / `.env.production`，或在部署平台配置：

| 配置 | 可选值 | 含义 |
| --- | --- | --- |
| `MTBED_UPLOAD_URL_PRIMARY` | 任意合法 URL | 备用图床主节点的上传地址 |
| `MTBED_UPLOAD_URL_SECONDARY` | 任意合法 URL | 备用图床备节点的上传地址 |

```dotenv
MTBED_UPLOAD_URL_PRIMARY=https://aapi.helioho.st/upload.php
MTBED_UPLOAD_URL_SECONDARY=https://mtbed.netsons.org/upload.php
```

现有图床继续沿用已有的 `IMGBB_API_URL`、`IMGBB_API_TOKEN`，无需改动。单次上游请求超时为固定的 15 秒，定义在 `service/fileUpload.ts` 的 `UPLOAD_TIMEOUT_MS`。

**默认线路是备用图床的主节点**，这条规则写在代码里（`lib/image-upload-routes.ts` 的 `DEFAULT_UPLOAD_ROUTE`），不占环境变量。换域名只改上面两个地址即可。

### 界面上临时切换线路

`components/ui/image-upload.tsx` 顶部提供「上传线路」下拉框，三个选项：备用 · 主节点（默认）、备用 · 备节点、现有图床。选中结果以固定 id 通过 FormData 的 `route` 字段下发。

服务端只认 `mtbed-primary`、`mtbed-secondary`、`default` 三个 id；缺省或任何其他值（包括任意 URL）都会回退到默认线路，浏览器始终无法指定上传地址。上传进行中下拉框会禁用。`<ImageUpload showRouteSelect={false} />` 可隐藏该下拉框。

修改后重启开发/生产服务；部署平台更新环境变量后重新部署。已有图片 URL 不会自动搬迁，切换只影响后续上传。

这是手动切换，不会在失败或超时后自动把同一张图片再次发送给另一个服务，以免产生重复文件或出现难以判断的上传结果。

## 2. 接入位置和接口契约

上传链路：

```text
头像 / 文章封面 / 图集 / Markdown 编辑器
  → lib/utils.ts：uploadImagePromise(file)
  → service/fileUpload.ts：uploadImage(formData)
  → 服务端所选上传源
```

前端仍调用 `uploadImagePromise(file): Promise<string>`，成功得到图片 URL，失败会拒绝 Promise 并按调用入口显示提示。编辑器使用自己的上传提示；其他入口由公共上传函数显示错误。

Server Action 的内部结果统一为 `{ code, message, data }`，成功时 `code=200`、`data={ url }`，失败时 `data=null`。仅归一化真实返回的 URL，不补造上游没有返回的宽高、文件 ID 等元数据。

| 上传源 | 地址 | 文件字段 | 请求参数与凭据 |
| --- | --- | --- | --- |
| `default` | 原 `IMGBB_API_URL` + `/api/v3/upload` | `file` | 原 Bearer Token；服务端设置 `dedup=true`、`album_id=1516` |
| `mtbed` / `primary` | [aapi.helioho.st/upload.php](https://aapi.helioho.st/upload.php) | `image` | 不携带现有图床的 Token 和相册参数；必须带 `Referer: https://695402.xyz/mt/`、`Origin: https://695402.xyz`、浏览器 UA，否则 403 |
| `mtbed` / `secondary` | [mtbed.netsons.org/upload.php](https://mtbed.netsons.org/upload.php) | `image` | 同上（备节点实测比主节点慢，约 5.9s vs 0.9s） |

备用源的成功契约来自该站公开前端代码：`code === 200`，图片地址取 `data.url`。这不代表第三方已向本项目承诺开放 API 或永久存储。

## 3. 校验与错误处理

- 服务端先检查登录身份，未登录不向上游发送图片。此前发现的生产 `AUTH_SECRET` 配置问题仍需按项目认证文档处理，否则上传会返回认证失败。
- 客户端预检和服务端共用大小单位解析；原 `NEXT_PUBLIC_IMG_UPLOAD_LIMIT` 继续生效。支持 `3mb`、`512kb` 等单位，无单位数字沿用 MB 语义。
- 第三方单张上限进一步限制为 20 MiB，实际采用“项目配置限制”和“20 MiB”中更小的值。默认项目大小限制不会自动提高到 20 MiB。
- Server Action 请求体额外预留 512 KiB 给 multipart 字段与边界，避免刚好达到文件上限的合法图片因封装开销被拒绝。
- 检查非空文件与二进制文件头，支持 PNG、JPEG、GIF、WebP、BMP、ICO、可识别的 HEIC。SVG、AVIF 和不能识别的内容会返回格式错误。文件头检查不等同于完整解码校验。
- 上游收到的文件名和 MIME 根据检测到的内容归一化，不信任客户端填写的类型或扩展名。
- 上传目标由服务器配置和固定节点列表决定，不接受浏览器传入目标地址；拒绝上传请求的重定向。
- 只接受含有效 HTTP(S) URL 的成功响应，拒绝脚本协议、空地址和带用户名/密码的地址。
- 对认证、格式、大小、HTTP 拒绝、非 JSON 页面、错误返回、网络错误和响应读取超时分别处理。不会把上游 HTML 或内部堆栈返回给用户。

| 业务码 | 含义 |
| --- | --- |
| `400` | 缺少文件、空文件或参数错误 |
| `401` | 未登录或会话无效 |
| `413` | 超出当前源的大小限制 |
| `415` | 不支持或无法识别的图片格式 |
| `502` | 上游拒绝、异常响应或网络失败；若上游为 403，提示会包含 403 |
| `504` | 上传请求或响应读取超时 |

这些是 Server Action 结果里的业务码，不表示 HTTP 传输状态必然相同。头像与通用图片组件在失败后退出加载状态，保留原图片并允许再次选择同一文件。
